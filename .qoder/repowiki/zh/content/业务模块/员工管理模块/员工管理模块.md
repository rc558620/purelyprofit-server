## 简介
本文件为员工管理模块的综合技术文档，覆盖员工信息管理、排班系统、请假管理、薪资管理等核心功能。文档解释员工档案维护、员工状态变更、员工权限分配等业务逻辑，涵盖服务类实现细节、控制器接口设计、数据验证规则，并对排班算法、请假审批流程、薪资计算逻辑等复杂业务场景进行深入分析。同时提供 API 使用示例、数据模型说明、集成指南以及与考勤、薪酬、权限控制模块的协作关系。

**重大更新** 本次重构重点解决了高并发场景下的子账户槽位分配冲突问题，实现了员工角色与权限的实时同步机制，并修复了跨门店员工调动时的数据一致性问题。通过引入CAS（Compare-And-Swap）原子操作和增强的事务管理机制，显著提升了系统的稳定性和可靠性。

### 员工信息管理
- 功能范围：员工档案维护、状态变更（在职/离职）、个人资料更新
- 关键流程：
  - 创建员工：校验参数 → 写入档案 → 分配默认权限/角色 → 返回结果
  - 更新员工：读取旧档 → 参数校验 → 写入新档 → 记录变更日志
  - 离职处理：校验可离岗条件 → 状态置为"已离职" → 结束未完成排班/请假结算
- 数据模型：员工表包含基本信息、状态、权限标识、关联账户等字段
- 集成点：与权限控制模块联动，确保操作者具备相应权限；与工位模块协作，处理工位占用/释放

**重大更新** 引入了CAS并发安全机制和增强的事务保护，确保在并发场景下员工编号生成的原子性和数据一致性。

### 子账户槽位管理（核心并发安全修复）
- 功能范围：子账户槽位的分配、释放、状态管理
- **核心并发安全修复**：
  - **CAS原子抢占机制**：使用`updateMany`配合条件检查实现Compare-And-Swap操作，防止并发修改覆盖
  - **空槽位竞争解决**：多个并发请求同时抢占空槽位时，只有第一个成功的请求能完成分配
  - **已分配槽位保护**：对已分配的槽位进行原子更新，避免并发覆盖导致的资源泄漏
- **事务一致性增强**：将槽位分配、角色同步和登录账号创建纳入同一事务，确保操作的原子性
- **并发错误处理**：当检测到槽位被其他操作变更时，抛出明确的错误提示用户刷新重试

```mermaid
flowchart TD
Start(["开始槽位分配"]) --> CheckExisting{"检查是否存在现有槽位"}
CheckExisting --> |存在| CASUpdate["CAS原子更新已分配槽位"]
CheckExisting --> |不存在| FindEmptySlots["查找可用空槽位"]
FindEmptySlots --> LoopSlots{"遍历空槽位尝试分配"}
LoopSlots --> CASAttempt["CAS尝试抢占槽位"]
CASAttempt --> Success{"抢占成功?"}
Success --> |是| AssignSlot["分配槽位给员工"]
Success --> |否| NextSlot["尝试下一个槽位"]
NextSlot --> LoopSlots
AssignSlot --> SyncRole["同步员工角色到Staff表"]
SyncRole --> CreateLogin["创建/更新登录账号"]
CreateLogin --> Complete["分配完成"]
CASUpdate --> UpdateSuccess{"更新成功?"}
UpdateSuccess --> |是| SyncRole
UpdateSuccess --> |否| Error["抛出并发冲突错误"]
Error --> End(["结束"])
Complete --> End
```

**这是本次最重要的并发安全修复**，彻底解决了高并发场景下的槽位分配冲突问题，确保每个槽位只能被一个员工独占使用。

### 角色权限同步机制（重要修复）
- **角色同步问题修复**：
  - **Store ID过滤问题**：移除了冗余的store ID过滤条件，解决员工跨门店调动时角色同步失败的问题
  - **唯一性约束利用**：利用`Employee.linkedStaffId`的唯一性约束，通过`employeeProfile`条件唯一定位Staff记录
  - **实时权限同步**：员工角色更新时立即同步到Staff表的role和permissions字段
- **权限一致性保证**：确保前端显示的角色与实际登录权限完全一致，避免权限不一致导致的安全问题

## 性能考虑
- 查询优化：为常用过滤字段建立索引；使用分页与投影减少数据传输
- 事务与锁：批量排班/薪资计算使用事务，避免并发冲突
- 缓存策略：热点字典与查询结果使用缓存，降低数据库压力
- 异步处理：长耗时任务（如薪资计算）采用队列异步执行
- **并发安全优化**：CAS操作相比传统锁机制具有更高的并发性能和更低的死锁风险
- **事务粒度控制**：合理划分事务边界，在保证一致性的同时提升并发处理能力

**重大更新** 引入了CAS并发控制机制，相比传统的悲观锁方案，在保持数据一致性的同时显著提升了系统吞吐量。

## 故障排除指南
- 权限不足：检查装饰器与守卫配置，确认用户能力集合与所需权限匹配
- 数据不一致：排查事务边界与回滚逻辑，确保幂等性
- 排班冲突：检查冲突检测规则与时间重叠判定
- 请假异常：核对假期余额、节假日叠加与跨月处理逻辑
- **并发冲突问题**：检查CAS操作的条件是否正确，确认并发错误处理逻辑
- **角色不同步问题**：验证employeeProfile关联关系，检查store ID过滤条件是否被正确移除
- **槽位分配失败**：确认槽位状态和isAssigned标志位，检查事务是否完整执行
