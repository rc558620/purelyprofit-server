## 更新摘要
**所做更改**
- **新增代码验证服务**：引入 AuthCodeVerifyService 专门处理验证码的验证逻辑，提升验证码验证的安全性和可维护性
- **改进JWT认证守卫**：增强JWT策略的错误处理和用户身份验证流程，集成跨租户访问防护检查
- **强化登录失败保护**：通过 AuthLoginFailGuardService 实现基于Redis的登录失败计数和账号临时锁定机制
- **安全功能增强**：实现了更完善的并发冲突处理和跨租户数据污染防护

## 简介
本文件面向认证授权系统的使用者与维护者，系统性阐述基于 JWT 的认证机制、权限控制模型与子账户（Store Sub-Account）安全策略。文档从整体架构到关键组件逐层展开，覆盖认证流程、Token 生成与验证、权限继承与校验、子账户登录与限制等主题，并提供与数据库、Redis 缓存、装饰器与守卫等组件的集成说明，帮助初学者快速上手，同时为资深开发者提供足够的技术深度。

**重大架构重构** 认证系统经历了重大的模块化重构，将原本单体式的认证服务分解为多个专业化的微服务组件。新的架构不仅提升了代码的可维护性，还增强了系统的安全性和扩展性。通过引入专门的验证码登录服务、登录失败防护、密码操作编排、微信登录等服务，系统现在能够提供更精细化的认证控制和更好的用户体验。

**最新安全增强** 系统新增了代码验证服务（AuthCodeVerifyService），进一步增强了验证码验证的安全性；改进了JWT认证守卫的错误处理机制；并通过增强的登录失败保护机制有效防止暴力破解攻击。

## 核心组件
- **统一认证服务**：AuthProductAuthService 提供多产品范围的统一认证接口，支持验证码发送、用户注册、登录、密码管理等功能。
- **代码验证服务（新增）**：AuthCodeVerifyService 专门处理验证码的验证逻辑，提供统一的验证码验证接口，支持多种验证码类型的验证。
- **验证码登录服务**：AuthCodeLoginService 专门处理手机号+验证码的登录流程，支持登录即注册功能，具备完善的并发冲突处理能力。
- **登录失败防护服务**：AuthLoginFailGuardService 基于 Redis 实现登录失败计数和账号临时锁定，防止暴力破解攻击。
- **密码操作编排服务**：AuthPasswordOpsService 协调密码修改和重置流程，确保会话安全和审计日志记录。
- **盈利专属账户查找服务**：AuthProfitAccountLookupService 处理纯盈利系统的账户查找逻辑，包含跨租户冲突检测。
- **微信小程序登录服务**：AuthWechatLoginService 处理微信小程序的登录即注册流程，支持账号合并和微信信息同步。
- **封禁检查服务**：AuthBanGuardService 专门负责用户封禁状态检查，基于门店维度进行封禁判断，支持缓存优化和批量查询。
- **会员解析与缓存服务**：AuthMembershipResolverService 负责会员信息解析、权限计算、缓存管理和历史数据修复，现已增强跨租户访问防护。
- **员工激活工作流服务**：AuthStaffActivationService 处理邀请员工激活、席位配额管理和缓存失效逻辑。
- **验证码服务**：AuthCodeService 负责验证码的生成、存储、验证和清理，支持注册、登录和密码重置场景。
- **短信服务（重大升级）**：AuthSmsService 现在集成了完整的腾讯云服务，支持生产环境的真实短信发送，同时保持开发环境下的日志降级模式。
- **主认证控制器与服务**：负责登录、注册、密码操作、会话管理、能力查询等入口与业务逻辑。
- **purely-club 认证模块**：专为个人端用户设计的独立认证系统，支持独立的注册、登录、密码找回等功能。
- **purely-pulse 认证模块**：专为开发者设计的认证系统，现重构为轻量级实现，依赖主认证模块提供核心认证能力。
- **JWT 守卫与策略（已增强）**：负责解析请求中的 JWT，校验签名与有效期，并注入当前用户上下文，现已增强token处理和错误处理机制。
- **权限守卫与装饰器**：用于方法级权限校验与子账户访问阻断。
- **子账户服务**：提供子账户的读取、槽位管理与登录辅助能力。
- **用户资料服务**：提供用户资料查询、更新头像、昵称更新、实名认证等功能。
- **注册门店创建服务**：提供注册后的门店创建功能，支持完整的注册闭环流程。
- **基础设施**：Prisma 数据库访问、Redis 缓存、全局配置。

## 架构总览
认证授权系统采用"控制器-服务-守卫-策略-装饰器"的分层设计，结合数据库与缓存完成身份认证与权限控制。JWT 作为无状态凭证贯穿整个流程；权限控制通过守卫与装饰器在路由层进行拦截与判定；子账户登录由专门的服务与守卫协同处理，确保主账户与子账户的边界清晰。

**重大架构重构** 经过服务拆分后，认证系统现在采用了更加模块化和专业化的架构设计。新的服务分层不仅提高了代码的可维护性，还增强了系统的安全性和扩展性。每个服务都专注于特定的认证场景，提供了更精细化的控制能力和更好的错误处理机制。

**最新安全增强** 新增的代码验证服务和改进的JWT认证守卫进一步提升了系统的安全性，通过更严格的验证码验证流程和增强的JWT令牌处理机制，有效防止了各种安全威胁。

**新功能** AuthLoginFailGuardService 实现了基于 Redis 的登录失败计数和账号临时锁定机制。

  - 详细的审计日志记录

  - `AUTH_LOGIN_FAIL_LOCK_TTL_SECONDS`：锁定时长（秒）
  - `AUTH_LOGIN_FAIL_KEY_PREFIX`：Redis键前缀

- **Redis键格式**
  - 格式：`auth:login-fail:{productScope}:{loginAccount}`
  - 值：失败次数（整数）
  - TTL：锁定时长

- **开发者模式特殊处理**

### SMS冷却与速率限制

**更新** 新增SMS冷却功能，使用Redis setIfAbsent操作实现精确的速率限制，防止恶意刷短信攻击。

- **冷却机制原理**
  - 使用Redis的setIfAbsent操作实现原子性的冷却标记
  - 基于场景、产品范围和手机号的组合键进行独立冷却
  - 通过NX选项确保同一时间只有一个请求能够获取冷却令牌

- **支持的冷却场景**
  - 注册场景：`auth:sms-cooldown:register:{productScope}:{phone}`
  - 登录场景：`auth:sms-cooldown:login:{productScope}:{phone}`
  - 密码重置场景：`auth:sms-cooldown:password-reset:{productScope}:{phone}`
  - 登录或注册场景：`auth:sms-cooldown:login_or_register:{productScope}:{phone}`

- **冷却配置**
  - 默认冷却时间为60秒（可通过配置调整）
  - 支持禁用冷却功能（冷却时间为0）
  - 每个场景独立配置，避免相互影响

- **异常处理**
  - 冷却期间返回HTTP 429状态码
  - 提供友好的错误消息："短信发送过于频繁，请 {seconds} 秒后再试"
  - 冷却结束后自动释放锁，允许下次发送

  - **重大更新** AuthSmsService集成了完整的腾讯云服务，支持生产环境短信发送
  - 简化了模块结构，减少了重复代码

## 性能考虑
- **验证码缓存优化**
  - 使用 Redis 缓存验证码，避免重复生成和发送
  - 设置合理的过期时间，平衡安全性和性能
  - 支持测试环境直接显示验证码，提高开发效率

- **短信服务降级优化（重大升级）**
  - **重大功能升级** 实现了智能的降级机制，当未配置腾讯短信凭证时自动回退到开发模式
  - 生产环境下通过腾讯云短信API发送真实短信，提升用户体验
  - 开发环境下记录验证码到日志，便于调试和测试
  - 短信发送失败时自动回滚缓存操作，确保数据一致性
  - 提供详细的日志记录，便于监控和故障排查
  - 支持异步发送，避免阻塞主线程

- **Token 缓存与降级**
  - 对频繁访问的用户能力进行缓存，降低数据库压力
  - 在缓存不可用时采用降级策略
  - 参考：[redis.service.ts:1-200](file://src/redis/redis.service.ts#L1-L200)、[auth-capability.service.ts:1-200](file://src/purely-profit/auth/auth-capability.service.ts#L1-L200)。

## 故障排除指南
- **验证码相关问题**
  - 现象：验证码发送失败或无法接收
  - 排查：检查短信服务配置、网络连接、Redis 缓存状态
  - 参考：[auth-code.service.ts:74-83](file://src/purely-profit/auth/auth-code.service.ts#L74-L83)、[auth-sms.service.ts:196-199](file://src/purely-profit/auth/auth-sms.service.ts#L196-L199)

- **Token 无效或过期**
  - 现象：请求被拒，提示鉴权失败。
  - 排查：确认 Token 是否正确携带、是否在有效期内、签名算法与密钥是否一致。
  - 参考：[jwt.strategy.ts:1-200](file://src/purely-profit/auth/strategies/jwt.strategy.ts#L1-L200)、[auth.constants.ts:1-41](file://src/purely-profit/auth/auth.constants.ts#L1-L41)。

- **权限不足**
  - 现象：方法级权限校验失败。
  - 排查：核对装饰器声明的权限集合与用户实际能力，检查主体能力计算逻辑。
  - 参考：[require-permissions.decorator.ts:1-200](file://src/purely-profit/access-control/decorators/require-permissions.decorator.ts#L1-L200)、[permissions.guard.ts:1-200](file://src/purely-profit/access-control/guards/permissions.guard.ts#L1-L200)。

- **子账户被阻断**
  - 现象：子账户访问被拒绝。
  - 排查：确认目标接口是否使用了阻断装饰器或守卫，必要时切换为主账户登录。
  - 参考：[block-sub-account.decorator.ts:1-200](file://src/purely-profit/access-control/decorators/block-sub-account.decorator.ts#L1-L200)、[sub-account-block.guard.ts:1-200](file://src/purely-profit/access-control/guards/sub-account-block.guard.ts#L1-L200)。

- **数据不一致**
  - 现象：权限或能力与预期不符。
  - 排查：检查数据库与缓存一致性，必要时清理缓存并重算能力。
  - 参考：[prisma.service.ts:1-200](file://src/prisma/prisma.service.ts#L1-L200)、[redis.service.ts:1-200](file://src/redis/redis.service.ts#L1-L200)。

- **认证范围错误**
  - 现象：用户无法登录或被拒绝。
  - 排查：确认用户所属的认证范围，检查账户类型与登录接口匹配性。
  - 参考：[auth-account.types.ts:1-20](file://src/shared/auth/auth-account.types.ts#L1-20)。

## 结论
本认证授权系统以 JWT 为核心凭证，结合守卫与装饰器实现细粒度的权限控制，并通过主体能力服务构建可扩展的权限继承模型。经过重大架构重构和安全增强后，系统现在具备了更加专业化和模块化的认证服务能力。

**重大架构重构总结** 
- **服务拆分与专业化**：将单体认证服务拆分为多个专业化服务，包括验证码登录服务、登录失败防护服务、密码操作编排服务、盈利专属账户查找服务、微信小程序登录服务和代码验证服务
- **安全功能增强**：实现了基于 Redis 的登录失败计数和账号临时锁定机制，有效的跨租户冲突检测和防护，以及增强的JWT认证守卫
- **并发处理优化**：新增的登录即注册流程具备完善的并发冲突处理能力，确保高并发场景下的数据一致性
- **会话安全管理**：密码操作编排服务实现了智能的会话管理和token版本控制，确保密码修改后的安全性
- **微信生态集成**：微信小程序登录服务支持账号合并、微信信息同步和安全的手机号绑定
- **验证码验证增强**：新增的代码验证服务提供了统一的验证码验证接口，增强了验证码验证的安全性

这些架构重构和安全增强通过精确的用户身份验证、严格的权限匹配策略、完善的错误处理和详细的日志记录，显著提升了系统的整体安全性、可靠性和用户体验。系统现在能够有效防止跨租户数据污染，保护多租户环境下的数据安全，同时为用户提供更加流畅和安全的认证体验。

purely-club 和 purely-pulse 认证模块通过独立的认证入口实现了产品范围的完全隔离，既保证了各业务线的独立性，又保持了统一的认证体验。purely-pulse 认证模块已成功重构为轻量级实现，通过依赖注入的方式复用主认证模块的核心能力，简化了模块结构，提高了代码复用率和维护性。

子账户体系通过登录服务、槽位服务与阻断守卫形成闭环，既保证灵活性又强化安全边界。配合数据库与缓存的合理使用，系统可在保证安全性的同时兼顾性能与可维护性。新的服务架构和安全机制为未来的业务扩展和维护提供了更好的基础。
