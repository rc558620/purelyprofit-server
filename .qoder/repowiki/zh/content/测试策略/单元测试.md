## 测试基础设施重大改进

### spec-matchers 库概述

项目引入了专门的 spec-matchers 库，提供一系列严格的 Jest 非对称匹配器，用于替代宽松的类型占位断言。这些匹配器实现了 Jest 的 AsymmetricMatcher 接口，可直接用于 `expect(...).toEqual/toMatchObject/toHaveBeenCalledWith` 的嵌套字段中。

**核心设计理念**：
- 对可推导的值，测试中应优先使用精确值
- 对确实动态生成、无法在断言点拿到精确值的字段（进程指标、耗时、锁 token、邀请码等），使用匹配器做「格式/约束断言」
- 比宽松类型占位更严格，能拦截空串、NaN、负数、非法格式、Invalid Date、空集合等问题

### 提供的匹配器类型

#### 基础类型验证
- **aNonNegativeNumber**: 非负有限数字，拒绝 NaN / Infinity / 负数 / 非数字
- **aNonEmptyString**: 非空字符串，拒绝空串与非字符串  
- **aValidDate**: 合法 Date 实例，拒绝 Invalid Date（如 new Date('')）
- **aNonEmptyObject**: 非空普通对象（非 null、非数组、非 Date、且至少有一个自有属性）
- **aNonEmptyArray**: 非空数组，至少包含一个元素
- **aNonEmptySet**: 非空 Set，至少包含一个元素

#### 业务特定格式验证
- **aUuid**: UUID v4 格式字符串验证
- **anInviteCode**: 门店邀请码格式验证（8 位，字符集 23456789ABCDEFGHJKLMNPQRSTUVWXYZ）
- **aDateOrObject**: 合法 Date 或「非空普通对象」二选一，用于模糊字段的严格验证

## 严格不等式匹配器详解

### 实现原理

所有匹配器都遵循相同的实现模式，通过实现 Jest 的非对称匹配器接口来提供自定义断言逻辑：

```typescript
const JEST_ASYMMETRIC_MATCHER = Symbol.for('jest.asymmetricMatcher');

export const aNonNegativeNumber = {
  $$typeof: JEST_ASYMMETRIC_MATCHER,
  asymmetricMatch: (actual: unknown): boolean =>
    typeof actual === 'number' && Number.isFinite(actual) && actual >= 0,
  toString: (): string => 'aNonNegativeNumber(>=0 finite number)',
};
```

#### 宽松断言的问题
