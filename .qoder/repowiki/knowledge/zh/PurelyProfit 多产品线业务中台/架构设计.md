- **统一认证与产品隔离**：基于 `JwtStrategy` 解析 JWT 载荷中的 `accountScope`，并通过 `JwtAuthGuard`、`ClubJwtAuthGuard` 等守卫实现不同产品线（Profit/Club/Pulse）的接口访问隔离。
- **全局上下文编排**：在 `main.ts` 启动时注册全局 `ValidationPipe` 与 HTTP 观测钩子；各产品线通过自定义拦截器（如 `ClubCurrentContextInterceptor`）或模块级服务（如 `PulseStoreContextService`）在请求链路中动态注入当前门店或会话状态。
- **共享基础设施依赖**：所有业务子模块均依赖全局注册的 `PrismaModule`（数据持久化）、`RedisModule`（缓存与分布式锁）以及 `AccessControlModule`（细粒度权限校验），确保底层能力的一致性。
- **跨域缓存协同**：通过 `cache-invalidator.registry.ts` 提供的注册表模式，将分散在各业务域的缓存失效逻辑聚合，由统一的 `CacheInvalidatorService` 驱动 Redis 键的精准清理。
