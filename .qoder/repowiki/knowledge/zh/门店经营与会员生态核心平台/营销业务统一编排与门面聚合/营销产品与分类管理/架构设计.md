- **分层架构**：采用 Controller -> Facade Service -> Domain Service 的分层模式。`MarketingProductsController` 和 `MarketingProductCategoriesController` 处理 HTTP 请求与权限校验；`MarketingProductsFacadeService` 作为外观层聚合产品与分类的业务逻辑；`MarketingProductsService` 和 `MarketingProductCategoriesService` 负责具体的数据库交互与业务规则实现。
- **依赖注入**：Controller 统一注入 `MarketingService`（即 `MarketingFacadeService` 的别名），而 Facade 内部组合了具体的领域服务，实现了接口暴露与内部实现的解耦。
- **数据访问**：底层通过 `PrismaService` 访问数据库，并依赖 `MarketingSharedService` 处理跨模块的门店权限校验与实体查找逻辑。
- **关键文件**：入口控制器为 `marketing-products.controller.ts`，核心业务逻辑分布在 `marketing-products.service.ts` 和 `marketing-product-categories.service.ts`，聚合层为 `marketing-products.facade.service.ts`。
