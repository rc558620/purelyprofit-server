- 采用 Controller-Facade-Service 三层架构：`MarketingOverviewController` 负责 HTTP 接口定义与权限校验，`MarketingOverviewFacadeService` 作为业务门面转发请求，`MarketingOverviewService` 承载核心数据聚合与持久化逻辑。
- 依赖 `PrismaService` 进行数据库交互（如 `marketingCustomer`、`marketingRecharge`、`marketingMemberLevelSetting`），并集成 `RedisService` 实现概览数据的缓存与自动刷新机制。
- 通过 `MarketingSharedService` 处理门店权限解析与访问控制，确保多租户环境下的数据隔离。
- 使用 DTO 类（位于 `dto/` 目录）严格定义请求参数与响应结构，并通过 Swagger 装饰器生成 API 文档。
