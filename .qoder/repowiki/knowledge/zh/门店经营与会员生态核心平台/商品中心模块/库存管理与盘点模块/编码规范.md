- 库存变更采用“计划-执行”模式：先在 Domain 层构建 `InventoryStockMutationPlan` 计算变更后库存并校验合法性，再在 Query 层执行数据库更新与日志记录。
- 所有涉及库存变动的操作（手动调整、销售扣减、采购入库）均强制写入 `inventoryAdjustmentLog` 表以保留审计轨迹。
- 库存预警等级统一划分为 'danger' (stock <= 0)、'warning' (0 < stock <= threshold) 和 'normal' 三级，并在查询结果中动态计算返回。
- API 响应中的 ID 字段统一转换为字符串类型，时间戳统一转换为毫秒级数字格式，以保持前端消费的一致性。
