- **分层架构**：采用 Controller-Service 模式，`NotificationsController` 负责 API 入口与权限校验，`NotificationsService` 编排核心逻辑。
- **职责拆分**：内部通过多个专用 Service 解耦：`NotificationsBuildService` 负责从 Prisma 聚合库存、财务、营销等业务数据生成通知草稿；`NotificationsContextService` 处理门店上下文与权限解析；`NotificationsReadStateService` 封装基于 Redis 的已读状态读写。
- **工具层**：`notifications.query.ts` 和 `notifications.mapper.ts` 分别处理内存分页/过滤逻辑与 DTO 映射，保持主服务纯净。
- **依赖方向**：模块依赖 `CommerceModule` 进行权限校验，依赖 `PrismaService` 获取业务数据，依赖 `RedisService` 持久化用户交互状态。
