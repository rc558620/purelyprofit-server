- 所有涉及状态流转或余额变动的写操作（如申请、审核、拒绝）均包裹在 `prisma.$transaction` 中以保证数据一致性。
- 在执行状态更新前，通过 `updateMany` 配合 `where` 条件中的当前状态进行乐观锁检查，若影响行数不为 1 则抛出 `ConflictException`。
- DTO 中的字符串字段（如账号、姓名）统一使用 `@Transform` 装饰器配合 `trim()` 进行预处理，并在 Service 层再次校验非空。
- API 响应遵循统一模式，写操作成功后返回包含最新提现记录（`record`）和实时汇总信息（`overview`）的组合 DTO。
