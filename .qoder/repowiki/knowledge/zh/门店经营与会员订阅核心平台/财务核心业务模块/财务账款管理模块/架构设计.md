- 入口层：`FinanceController` 统一暴露 `/finance` 路由，通过 `JwtAuthGuard` + `PermissionsGuard` 进行认证与权限校验，并将请求委托给门面服务 `FinanceService`。
- 门面层：`FinanceService` 作为协调者，将业务分发至四个领域服务：`FinanceOverviewService`（总览/报表）、`FinanceCashFlowService`（流水）、`FinanceAccountService`（账款）、`FinanceReconciliationService`（对账）。
- 领域服务层：以 `FinanceAccountService` 为例，采用“访问控制 -> 缓存查询/更新 -> 领域逻辑 -> 数据查询”的处理链路。依赖 `FinanceAccessService` 获取并校验当前门店ID及财务功能开通状态；使用 `RedisService` 结合 `finance.cache-keys` 实现列表与统计数据的短 TTL 缓存及后台刷新；调用 `*.domain.ts` 执行状态推导、规则校验与 DTO 映射；调用 `*.query.ts` 执行 Prisma 数据库操作。
- 数据访问层：`*.query.ts` 文件封装 Prisma Client 的 CRUD 操作，定义统一的 Select 投影与 Where 构建逻辑，确保查询性能与字段一致性。
- 支撑层：`dto/` 目录严格区分 Query DTO（输入验证）与 Response DTO（输出结构）；`*.utils.ts` 提供金额精度处理、分页计算、日期范围等通用工具；`finance.types.ts` 定义内部共享类型。
