- 采用“查询-映射-工具”分离模式，将数据检索（`.query.ts`）、对象转换（`.mapper.ts`）与业务逻辑计算（`.utils.ts`）拆分为独立文件。
- 在 Service 层实施“缓存优先”策略，先尝试从 Redis 获取序列化后的响应对象，未命中时再执行数据库查询并回写缓存。
- 使用 Prisma 的 `validator` 和 `Select` 类型定义严格的数据库字段选择器，确保数据传输的最小化与类型安全。
- 通过 `buildCapabilitySnapshot` 方法集中处理用户身份与门店权限的交叉验证，并将结果作为响应的一部分返回给前端以驱动 UI 显隐。
