- **分层架构**：采用 Facade 模式，`MarketingFacadeService` 作为统一入口协调各子域（顾客、交易、促销、产品）的 Facade 服务。
- **职责划分**：`MarketingAccessService` 负责门店维度的权限拦截；`MarketingSharedService` 封装通用的实体查找与异常抛出逻辑；`marketing.query.ts` 集中管理原生 SQL 查询以优化性能；`marketing.mapper.ts` 负责数据库行到 DTO 的转换。
- **类型隔离**：通过 `marketing.utils.ts` 和 `marketing.types.ts` 定义纯函数与接口，避免在 Service 层直接依赖带有装饰器的 DTO 类，实现业务逻辑与 API 契约的解耦。
