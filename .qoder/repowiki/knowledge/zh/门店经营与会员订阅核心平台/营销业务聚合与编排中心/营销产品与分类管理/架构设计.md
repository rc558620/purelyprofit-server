- **分层架构**：采用 Controller -> Facade Service -> Domain Service 的分层模式。`MarketingProductsController` 和 `MarketingProductCategoriesController` 处理 HTTP 请求与权限校验；`MarketingProductsFacadeService` 作为统一入口聚合产品与分类的业务逻辑；`MarketingProductsService` 和 `MarketingProductCategoriesService` 负责具体的数据库操作与业务规则校验。
- **依赖方向**：Controller 依赖 `MarketingService`（即 `MarketingFacadeService` 的别名导出），Facade 内部组合调用具体的领域服务，领域服务依赖 `PrismaService` 进行数据持久化以及 `MarketingSharedService` 进行跨模块的门店权限校验。
- **关键文件**：`marketing-products.facade.service.ts` 定义了模块对外的服务接口边界；`marketing-products.service.ts` 实现了核心的 CRUD 逻辑与门店归属校验。
