- 采用“计划-执行”模式处理库存变更：先在 Domain 层构建变更计划（Plan），再在 Query 层执行数据库更新与日志写入，确保逻辑清晰且易于测试。
- 所有涉及库存变动的操作（如手动调整、销售扣减）均通过 Prisma Transaction (`$transaction`) 保证数据一致性，并同步写入 `inventoryAdjustmentLog` 流水表。
- 库存预警等级（danger/warning/normal）的计算逻辑统一收敛在 `inventory.domain.ts` 的 `resolveInventoryAlertLevel` 函数中，避免多处重复实现。
- API 响应中的 ID 字段统一转换为字符串类型（如 `String(product.id)`），以避免前端大数精度丢失问题。
- 查询接口支持多条件组合筛选（关键字、分类、预警等级等），并在 Service 层通过 `matchesInventoryFilters` 进行内存过滤或 Prisma `where` 子句动态构建。
