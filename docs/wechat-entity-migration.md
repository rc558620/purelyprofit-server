## 〇、先搞清楚这次迁移在解决什么

当前平台上有**两个主体**，资产分散在两边，这正是「小程序支付无法调起」的根因：

| 主体 | 证件类型 | 名下资产 |
|------|---------|---------|
| 纯利宝（昆明）科技有限公司 | 有限公司 | 微信支付**服务商商户号** `1004668090`、服务号 `f0rest2012`（`wx06bb1d38761675aff`）、壳小程序「纯利宝3」`wx8ff77307a74a564f`（本次临时创建） |
| 官渡区纯利堡软件开发服务部 | 个体工商户 | **purelyClub 小程序** `wxb2533a73dc3764b5`、门店收款子商户号 `1004782093`、平台旧收款商户号 `1001008587` |

微信硬规则导致卡点：

1. 服务商 `sp_appid` **必须是服务商同主体的小程序**，且必须与 `sp_mchid` 绑定；
2. 服务号不能代替小程序做下单主体（小程序 `wx.requestPayment` 只能拉起小程序 appid 生成的 `prepay_id`）；
3. 服务商**无法关联不同主体**的小程序（后台提示「当前商户号暂不支持关联主体不一致的 AppID」）；
4. 因此目前只能用「壳小程序当 `sp_appid` + purelyClub 当 `sub_appid`」的过渡方案，且**每个商家（子商户号）都要单独关联一次 club appid**，缺一个就报
   `商户号mch_id与appid不匹配` / `APPID_MCHID_NOT_MATCH`。

**迁移目标**：把所有资产统一到「纯利宝（昆明）科技有限公司」，使 `sp_appid` 直接等于 purelyClub 小程序 appid，`sub_appid` 退场，壳小程序下线。

## 二、总体顺序（两条线并行，支付线内部严格串行）

支付链路**当前已经跑通**（变更日志 2026-11-14：「壳小程序 + sub_appid」真机支付已通）。因此本次迁移不是上线前置，两条线分开排期：

```
线 A · 合规线（不阻塞上线，可与线 B 并行）
  T+0      阶段 0  准备：材料、信息核对、3.3 的 4 项待确认
  T+0      阶段 1  域名过户实名 + 新短信签名并行申请（不影响线上）
  T+1~2           短信签名通过 → 灰度切换 → 观察
  T+3~    阶段 2  ICP 备案：注销原备案 → 昆明科技重备（域名不变）
                    └ 排期取决于 5.5 的确认结果：并行口径 2~4 周 / 串行口径 4~8 周

线 B · 支付线（先变更、再上线，内部严格串行，不依赖阶段 2）
  T+0      阶段 3  解绑非目标主体商户号 → 小程序主体变更（微信侧，1~2 周）
                    └ 解绑起支付中断，变更审核期间不允许重新绑定
  T+7~14   阶段 4  微信支付关联重建：服务商 → 各子商户 →（必要时）平台收款号
  T+7~14   阶段 5  配置切换（.env）+ 重启 + 灰度
  T+7~14   阶段 6  验证：商家端校验 + 真机小额支付 + 回调入账
  T+14~    上线     支付已是目标态 + 短信签名就绪 → 发版
  稳定后    阶段 7  旧资产下线：壳小程序、旧商户号、旧签名
```

**为什么可以这样拆**：

- 阶段 3 是微信侧动作，与 ICP 备案、域名、短信签名**无依赖关系**，不需要等备案下证；但它要求先解绑非目标主体商户号，**会中断当前支付**（6.4），因此只能安排在无用户阶段做；
- 阶段 2 只影响「域名对大陆公网提供服务」；现状是域名已备案且可服务（主体为个体户），**不主动注销就不会中断**。主体不一致是合规瑕疵，不是运行阻断；
- 阶段 1 是阶段 2 的前置（域名实名主体不符会被备案审核驳回），但只约束合规线，不约束支付线；
- 阶段 4、5 必须在阶段 3 完成后做，否则会重现 `APPID_MCHID_NOT_MATCH`；
- 阶段 7 放最后，因为旧资产是回滚的退路。

**三条铁律**：

1. 阶段 3 完成前，**不要动 `.env`**，现有「壳小程序 + sub_appid」口径继续承接线上支付；
2. 任何阶段都不允许批量改写存量订单里的 `sp_mch_id` / `sub_mch_id`（历史对账依据）；
3. 每次配置变更后必须真机小额支付验证，不能只看后台状态。

## 五、阶段 2：ICP 备案（云南：必须注销重备，域名不变）

> 2026-11-14 已向腾讯云核实的只有 **5.1 的云南跨主体口径**；5.5 的排期前提与 5.7 的微信侧小程序备案仍属「⚠️ 待确认」（见 3.3），不要混为一谈。

### 5.1 结论

| 问题 | 云南管局口径 |
|------|-------------|
| 跨主体（个体工商户 → 有限公司）能否「变更备案」 | ❌ 不能。两者统一社会信用代码不同，属于「A 企业 → B 企业」 |
| 域名要不要换 | ✅ **不用换**，继续用原域名 |
| 域名需要做什么 | 持有者实名过户到昆明科技（或法定代表人） |
| 网站会中断吗 | ⚠️ 会。注销原备案后、新备案通过前，域名无法对大陆公网提供服务 |

云南只接受「同一主体更名」（需工商更名函）与「个人转企业」（限原个人主体为该企业法定代表人）。个体户与有限公司之间不属于上述任何一种，不在可变更范围内。

### 5.2 关键影响：备案空窗 ≠ 上线前置

微信小程序要求服务器域名必须是**已备案**域名；注销原备案后到新备案下证前，域名无法对大陆公网提供服务。但要分清三件事：

- ✅ **现状**：域名已备案且可正常服务（主体为个体户），不主动注销就不会中断；
- ⚠️ **重备时**：那一次空窗会中断域名接入，影响小程序请求与 Web 访问，必须挑无用户或低峰窗口；
- ✅ **结论**：备案重备是「什么时候付空窗成本」的排期问题，**不是上线前置**（见二之三路线 C）。

### 5.3 执行顺序（腾讯云确认稿 + 待确认前置）

1. [ ] 回收 3.3 的 4 项确认，据此判定昆明科技走「首次备案」还是「新增备案」；**不要把「新主体在案记录为空」当既定前提**
2. [ ] 域名持有者过户 / 实名改为昆明科技全称或法定代表人
3. [ ] 腾讯云账号实名认证变更为昆明科技（账号实名须与备案主体一致）

## 十二、常见坑

| 现象 | 根因 | 处理 |
|------|------|------|
| `商户号mch_id与appid不匹配`（`INVALID_REQUEST`） | `sp_appid` 与服务商号未绑定，或用了服务号 appid | 换服务商同主体**小程序** appid；检查关联状态 |
| `appid和mch_id不匹配`（`APPID_MCHID_NOT_MATCH`） | `sub_appid` 未与子商户号绑定 | 为该子商户号单独关联 appid |
| 商家端显示「已生效」但下单失败 | 旧版本校验只查了子商户关系 | 已修复：现在绑定校验会同时探测 AppID 维度 |
| 小程序能拉起但支付被拒 | `paySign` 的 appid 与实际调起的小程序不一致 | 现在由 `subAppId ?? appId` 决定，切换后自动一致 |
| 回调解密全部失败 | 平台证书按商户号维度下发，换号未换证书 | 重新下载该商户号维度的平台证书 |
| 备案审核驳回 | 域名实名主体与备案主体不一致 | 先过户域名并实名，再提交备案 |
| 小程序请求 403 / 域名不可用 | 备案重备空窗，或服务器域名白名单与实际域名不一致 | 本次域名不变，重点检查备案状态；白名单在公众平台 → 开发管理 → 服务器域名核对 |
| 主体变更页「去解绑」跳转后没有解绑按钮 | 小程序后台「商户号管理」只做展示，解除入口在商户平台 / 服务商侧 | 特约商户：服务商平台 → 合作伙伴功能 → 特约商户管理 → 该子商户 → AppID 账号管理；普通商户：`pay.weixin.qq.com` → 产品中心 → AppID 账号管理；仍无入口联系微信支付客服 95017 |
| 在服务商号自己的「AppID 账号管理」里找解除按钮 | 该页只列服务商已关联的服务号 / 壳小程序，**不含**子商户的 appid 关联 | 不要在这里操作；误解除壳小程序会让当前 `sp_appid` 立即失效 |
