# purelyClub 扫码点餐接口需求说明

## 1. 文档目的与范围

本文定义 `purelyClub` 消费者端扫码点餐的业务边界、接口范围、权限规则、金额口径、状态机和联调验收标准。

- 消费者端：`purelyClub` 微信小程序。
- 商家端：`purelyProfit`，继续使用既有 `/api/profit/scan-ordering` 管理接口。
- 服务端：`purelyprofit-server`。
- 消费者端 API 前缀：`/api/club/scan-ordering`。
- 订单、菜单、桌台和库存以服务端 `ScanOrdering*` 领域模型为唯一事实来源。

本文不包含商家端菜单、桌台、二维码和履约管理接口的重新设计；这些能力由已有商家端模块维护。

## 2. 已确认业务决策

| 决策项     | 约定                                                                                                         |
| ---------- | ------------------------------------------------------------------------------------------------------------ |
| 用户身份   | 用户可先扫码解析桌码；建立会话、购物车、下单、支付、订单查询和服务呼叫必须登录。                             |
| 门店归属   | 扫描桌码确定目标门店和桌台；请求体中的 `storeId` 不能作为可信来源。                                          |
| 同桌模式   | 首期按“个人订单、共享桌台”设计。用户只能查询和操作本人订单；桌台状态由全部未完结订单聚合。                   |
| 购物车归属 | 购物车属于“当前用户 + 当前桌台会话”，不可作为其他用户或其他桌台的订单来源。                                  |
| 点餐金额   | 价格、规格加价、活动、会员优惠、优惠券、服务费、税费、应付金额均由服务端计算，金额存储和接口原始值统一为分。 |
| 支付确认   | 生产环境仅微信支付回调可确认支付成功；客户端不能调用成功确认接口。                                           |
| 支付时机   | 首期采用“先创建待支付订单，再拉起微信 JSAPI 支付”；支付成功后进入待接单。                                    |
| 未支付订单 | 默认支付有效期 10 分钟；超时或用户取消后释放库存预占与优惠券占用。                                           |
| 库存       | 有限库存下单时预占；支付成功确认，支付失败、超时、取消、商家拒单或退款按规则释放/回补。                      |
| 商家拒单   | 仅待接单订单可拒单；拒单后进入退款流程或原路退款，具体支付渠道动作由支付模块执行。                           |
| 服务呼叫   | 当前用户可对当前有效桌台会话发起呼叫；相同会话、类型 120 秒内只允许一次。                                    |

## 3. 核心业务对象

| 对象       | 所属领域       | 用途                                                             |
| ---------- | -------------- | ---------------------------------------------------------------- |
| 桌台二维码 | 商家扫码点餐域 | 将物理桌台安全映射为短期扫码凭据。                               |
| 点餐会话   | C 端扫码点餐域 | 锁定用户、门店、桌台与有效期，是购物车和点餐操作授权边界。       |
| 菜单       | 商家扫码点餐域 | 由分类、商品、规格、可售状态、库存组成，向 C 端输出脱敏视图。    |
| 购物车     | C 端扫码点餐域 | 保存用户当前未提交的商品与规格组合；每次写入都由服务端核验。     |
| 订单预览   | C 端扫码点餐域 | 按实时菜单、库存、会员权益、活动和券规则生成短时有效的价格快照。 |
| 点餐订单   | 商家扫码点餐域 | 支付、履约、退款、对账的唯一业务事实。                           |
| 支付尝试   | 支付域         | 同一订单的支付渠道交互及回调审计事实。                           |
| 服务呼叫   | C 端扫码点餐域 | 用户对桌台发起的服务请求，供商家端处理。                         |

## 4. 权限矩阵

| 操作                   | 匿名扫码者             | 已登录 C 端用户 | 商家员工                                   |
| ---------------------- | ---------------------- | --------------- | ------------------------------------------ |
| 解析桌码               | 允许                   | 允许            | 不适用                                     |
| 建立或恢复点餐会话     | 不允许                 | 仅本人          | 不适用                                     |
| 读取菜单               | 仅基于有效扫码解析结果 | 仅本人有效会话  | 通过商家端接口                             |
| 读写购物车             | 不允许                 | 仅本人有效会话  | 不适用                                     |
| 订单预览与创建         | 不允许                 | 仅本人有效会话  | 不适用                                     |
| 支付与查询支付状态     | 不允许                 | 仅本人订单      | 不适用                                     |
| 查询订单详情           | 不允许                 | 仅本人订单      | 同门店且具备权限                           |
| 接单、出餐、完成、拒单 | 不允许                 | 不允许          | 同门店且具备 `scan-ordering:order-process` |
| 呼叫服务员             | 不允许                 | 仅本人有效会话  | 查看并处理同门店呼叫                       |

## 5. 消费者端接口清单

### 5.1 扫码与会话

| 方法  | 路径                      | 鉴权 | 目的                                                |
| ----- | ------------------------- | ---- | --------------------------------------------------- |
| POST  | `/scan/resolve`           | 否   | 解析桌码，返回可展示的门店/桌台信息和短期扫码凭据。 |
| POST  | `/sessions`               | 是   | 使用短期扫码凭据建立或恢复用户桌台会话。            |
| GET   | `/sessions/current`       | 是   | 恢复当前用户的有效桌台会话。                        |
| PATCH | `/sessions/current`       | 是   | 更新就餐人数。                                      |
| POST  | `/sessions/current/leave` | 是   | 用户退出当前桌台会话，不等于清台。                  |

### 5.2 菜单与购物车

| 方法   | 路径                        | 鉴权 | 目的                              |
| ------ | --------------------------- | ---- | --------------------------------- |
| GET    | `/menu`                     | 是   | 获取当前会话所属门店的 C 端菜单。 |
| GET    | `/menu/products/:productId` | 是   | 获取商品及规格详情。              |
| GET    | `/cart`                     | 是   | 获取当前会话购物车。              |
| POST   | `/cart/items`               | 是   | 添加商品和规格组合。              |
| PATCH  | `/cart/items/:itemId`       | 是   | 更新商品数量，携带乐观锁版本。    |
| DELETE | `/cart/items/:itemId`       | 是   | 删除指定购物车行。                |
| DELETE | `/cart`                     | 是   | 清空当前会话购物车。              |

### 5.3 预览、订单与支付

| 方法 | 路径                        | 鉴权 | 目的                                       |
| ---- | --------------------------- | ---- | ------------------------------------------ |
| POST | `/orders/preview`           | 是   | 服务端重算完整价格和优惠拆解，不创建订单。 |
| POST | `/orders`                   | 是   | 使用幂等键创建待支付订单并返回支付参数。   |
| POST | `/orders/:orderId/payments` | 是   | 为未过期的待支付订单重新获取支付参数。     |
| POST | `/orders/:orderId/cancel`   | 是   | 取消本人未支付订单。                       |
| GET  | `/orders`                   | 是   | 查询本人当前会话或历史订单。               |
| GET  | `/orders/:orderId`          | 是   | 查询本人订单详情和状态历史。               |
| GET  | `/orders/:orderId/status`   | 是   | 查询本人订单状态，用于轮询。               |
| POST | `/service-calls`            | 是   | 发起呼叫服务员请求。                       |

支付回调保留在既有支付域，建议按订单类型扩展为扫码点餐订单：`POST /api/club/payments/wechat/callback`。

## 6. 统一契约规则

### 6.1 标识与时间

- 所有对外资源 ID 使用字符串返回，避免 JavaScript 大整数精度问题。
- 请求路径中的 ID 使用 URL 编码后的字符串。
- 时间均返回 ISO 8601 UTC 字符串，例如 `2026-07-23T12:00:00.000Z`。
- 分页使用游标，不使用高偏移量 `offset` 分页。

### 6.2 金额

- 所有 `*Amount` 字段均为整数，单位为分。
- `currency` 首期固定为 `CNY`。
- 服务端可以额外提供 `displayAmount`，但客户端只能展示，不能从其反向计算。
- 客户端不得提交价格、优惠金额、应付金额、支付金额、库存或订单状态。

### 6.3 请求追踪与幂等

- 所有响应必须透传或生成 `requestId`，异常响应同样返回该字段。
- `POST /orders` 必须携带 `Idempotency-Key` 请求头，格式为 UUID 或 ULID，最长 128 字符。
- 同一用户、同一幂等键、不同请求体返回 `409 IDEMPOTENCY_KEY_REUSED`。
- 同一用户、同一幂等键、同一请求体必须返回首次创建的同一订单结果。

### 6.4 缓存

- 菜单接口返回 `ETag`；客户端后续使用 `If-None-Match`，命中时返回 `304`。
- 会话、购物车、预览和订单写操作的响应禁止被共享 CDN 缓存。
- 菜单变更、商品上下架、库存状态变更、规格变更必须主动失效菜单缓存。

## 7. 订单状态机

### 7.1 主订单状态

| 当前状态             | 可迁移到             | 触发方         | 说明                                       |
| -------------------- | -------------------- | -------------- | ------------------------------------------ |
| `pending_payment`    | `pending_acceptance` | 支付回调       | 验签、金额核验、幂等确认支付后进入待接单。 |
| `pending_payment`    | `cancelled`          | 用户或超时任务 | 用户取消或支付超时。                       |
| `pending_acceptance` | `preparing`          | 商家           | 商家接单。                                 |
| `pending_acceptance` | `rejected`           | 商家           | 商家拒单；已支付时进入退款编排。           |
| `preparing`          | `served`             | 商家           | 标记已出餐。                               |
| `served`             | `completed`          | 商家           | 结账/完成。                                |
| `rejected`           | `refunding`          | 服务端         | 已支付订单进入退款中。                     |
| `refunding`          | `cancelled`          | 服务端         | 退款完成后订单关闭。                       |

除表中路径外，任何状态迁移均应返回 `409 ORDER_STATUS_CONFLICT`。每次迁移必须写入订单状态历史。

### 7.2 支付状态

| 支付状态    | 说明                                             |
| ----------- | ------------------------------------------------ |
| `unpaid`    | 尚未确认收到支付回调。                           |
| `paid`      | 支付回调已验签、订单金额已核验、支付流水已落库。 |
| `refunding` | 已发起退款且等待渠道确认。                       |
| `refunded`  | 渠道退款已确认。                                 |

### 7.3 履约状态

| 履约状态    | 说明                     |
| ----------- | ------------------------ |
| `preparing` | 待接单或制作中。         |
| `served`    | 已出餐。                 |
| `closed`    | 已完成、已取消或已拒单。 |

## 8. 关键业务规则

### 8.1 桌码与会话

1. 二维码只保存高熵随机 token 的哈希，接口与日志不得输出持久明文 token。
2. 桌码解析返回的扫码凭据为短期、单一用途凭据，不能直接作为长期会话令牌。
3. 点餐会话必须校验用户、门店、桌台、状态和到期时间。
4. 已禁用、清台中、已吊销二维码或不存在的桌台不能建立会话。
5. 用户退出会话不会清台；桌台清理仅由商家端在全部未完成订单结束后执行。

### 8.2 菜单、规格与购物车

1. 菜单只返回 C 端展示所需字段，禁止泄露进货价、毛利、后台权限与内部库存策略。
2. 购物车规格组合的唯一性由服务端按“商品 ID + 升序规格项 ID 集合”的稳定签名确定。
3. 服务端校验商品归属、规格组归属、单选/多选数量、商品/规格可售性和库存。
4. 购物车变更使用 `version` 乐观锁；版本冲突时返回完整或可重新加载的最新购物车。
5. 菜单价格或库存变化后，购物车读取和订单预览都必须重新校验。

### 8.3 价格、营销与优惠券

1. 订单预览必须从服务端实时计算，且返回商品原价、规格加价、优惠项、服务费、税费与应付金额。
2. 预览结果通过 `pricingVersion` 绑定购物车版本、菜单版本、会员权益版本和营销版本，默认有效期 5 分钟。
3. 创建订单必须重新计算，`pricingVersion` 只用于检测用户界面是否过期，不能替代服务端定价。
4. 优惠券在创建订单事务中锁定，支付成功后核销，取消、超时、拒单或退款按规则释放或恢复。
5. 同一优惠不可重复核销；优惠叠加、覆盖和优先级由服务端统一决定，并通过 `breakdownItems` 返回。

### 8.4 下单、库存与支付

1. 创建订单必须在短事务内完成会话校验、购物车读取、价格重算、库存预占、优惠券锁定、订单/订单项/状态历史写入和支付意图创建。
2. 事务内禁止调用第三方支付 HTTP 接口；支付参数生成放在订单持久化后的受控编排流程中。
3. 有限库存使用数据库条件更新或稳定顺序行锁，不能只依赖 Redis 扣减。
4. 订单创建、支付回调和退款回调均需数据库唯一约束与幂等处理。
5. 生产环境中客户端支付结果仅用于展示和触发查单，不能改变订单支付状态。

### 8.5 订单查询与服务呼叫

1. 默认用户只能读取自身订单；若未来支持同桌共享账单，必须新增明确授权模型，不能仅通过 `tableId` 放开。
2. 当前订单状态可轮询：待支付 2 秒一次且最多 60 秒，履约中 10 至 15 秒一次，终态停止。
3. 服务呼叫按“会话 + 呼叫类型”限流 120 秒，商家端处理后保留可审计状态。

| 403       | `SCAN_ORDER_FORBIDDEN`           | 无权查看或操作该订单。             |
| 404       | `SCAN_TABLE_NOT_FOUND`           | 桌台不存在，请重新扫码。           |
| 404       | `SCAN_PRODUCT_NOT_FOUND`         | 商品不存在或已下架。               |
| 409       | `SCAN_QR_REVOKED`                | 桌码已失效，请联系店员。           |
| 409       | `SCAN_TABLE_UNAVAILABLE`         | 当前桌台暂不可点餐。               |

```json
  "code": "STOCK_INSUFFICIENT",
  "message": "部分商品库存不足，请调整后重试。",
  "requestId": "req_01J...",
  "timestamp": "2026-07-23T12:00:00.000Z"
}
```

## 10. 前端对接边界

1. `purelyClub` 页面、组件、store 和工具函数不得计算任何业务金额。
2. 菜单页必须替换 `menu.mock`；确认订单页必须删除本地折扣和应付金额推导；订单追踪页必须以服务端订单为事实源。
3. `tableStore` 仅保存当前服务端会话 ID 和用于 UI 的桌台摘要；`cartStore` 和 `orderStore` 只能承担交互缓存，服务端响应优先级更高。
4. 页面不直接请求接口；请求、响应映射、错误归类位于 `src/services/`，页面状态由页面级 hook/controller 管理。
5. 菜单、购物车、预览、创建订单必须建模加载、空态、失败、重试、提交中和请求竞态。

## 11. 联调验收清单

- 桌码有效、无效、吊销、桌台禁用、桌台清台中。
- 未登录扫码、登录后建立会话、刷新后恢复会话、会话过期。
- 菜单缓存命中/失效、商品上下架、规格失效、商品售罄。
- 购物车规格组合、版本冲突、库存变化和跨店/跨用户越权。
- 预览金额、会员优惠、优惠券可用/不可用、优惠覆盖。
- 双击提交、网络超时重试、幂等重放、同幂等键不同参数。
- 支付取消、支付成功、重复回调、回调金额不一致、支付超时。
- 商家接单、出餐、完成、拒单、退款；C 端状态轮询与刷新恢复。
- 服务呼叫限流、商家处理、用户端结果反馈。
- 订单、库存、优惠券、支付流水和状态历史的一致性核对。

## 12. 进入数据库设计前的确认项

以下项目在第二步数据库设计评审前必须由产品、支付和商家运营确认：

1. 同桌是否允许共享查看全部订单、合并支付或代付。
2. 是否允许游客购物车，以及登录后如何合并。
3. 支付失败、商家拒单、部分缺货时的退款/补单策略。
4. 有限库存的预占时长和库存释放规则。
5. 优惠券与会员折扣的叠加优先级、退款后恢复规则。
6. 是否支持服务费、税费、打包费、配送费及其开关范围。
7. 桌台会话的默认有效期、续期上限和清台前置条件。
